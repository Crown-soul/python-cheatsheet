01for 的形狀
for 變數 in 清單:
    做事

冒號不能少，下一行一定要往右縮。縮進去的才算迴圈裡面。

02range 三個參數
range( 開始, 停止, 間隔 )

停止的那個數字不算在內。要算到 k 就寫 range( 1, k+1 )。

03累加器的三個位置
t = 0                      # 迴圈外面
for i in range( 1, k+1 ):
    t += i                 # 迴圈裡面
print( t )                 # 迴圈外面

三行分別在哪一層，比它們寫什麼還重要。t = 0 掉進迴圈裡，答案就會變成最後一個數字。

CH 1 · 讓電腦重複做事
01

同一件事做四次，就該用迴圈

四行程式長得一模一樣，只有中括號裡的編號在變——這就是迴圈要出場的訊號。

這是上一份筆記裡查成績的寫法。四行 print 疊在一起，看起來很長，但不一樣的只有 [0]、[1]、[2]、[3] 這四個數字。

2-3-1.py
score = [ 100, 85, 60, 59 ]
level = [ "good", "ok", "so..", "bad" ]

print( "分數： %3d ，程度： %s" % (score[0], level[0]) )
print( "分數： %3d ，程度： %s" % (score[1], level[1]) )
print( "分數： %3d ，程度： %s" % (score[2], level[2]) )
print( "分數： %3d ，程度： %s" % (score[3], level[3]) )
輸出分數： 100 ，程度： good
分數：  85 ，程度： ok
分數：  60 ，程度： so..
分數：  59 ，程度： bad

四個人要寫四行，一百個人就要寫一百行。而且改格式的時候，一百行都要改。迴圈就是用來講一句話：「這件事照著清單做一遍」。

  • %3d數字靠右對齊，不夠三位數就在左邊補空格，所以 85 前面多一個空格。
  • [0] ~ [3]四行裡唯一在變的東西。看到這種「只有編號在變」的重複，就是迴圈的位置。
動手試
把這四行數一數：總共有幾個字是真的不一樣的？答案是 4 個數字。其他全部都是複製貼上。
CH 2 · 把一堆東西一個一個拿出來
02

for 會把清單裡的東西一個一個拿出來

for 變數 in 清單，意思是「把清單裡的東西輪流放進這個變數，每放一次就做一次底下的事」。

清單（list）就是用中括號包起來、逗號隔開的一排東西。for 會從第一個開始，一個一個拿，拿完就停。

1.py
S = [ 0, 1, 2 ]

for i in S:
    print( i )
輸出0
1
2
  • S要走訪的清單。放在 for ... in 後面。
  • i每一輪用來接住「當下這個東西」的變數。名字自己取，叫 i、e、num 都可以。
  • :冒號不能少。少了會 SyntaxError。
  • 縮排冒號下一行要往右縮（按一次 Tab）。縮進去的才算迴圈裡面。
容易踩的坑
冒號忘了打，Python 會說 SyntaxError: expected ':'；冒號打了但下一行沒縮排，會說 IndentationError: expected an indented block after 'for' statement on line 1。這兩個是學迴圈最常遇到的錯誤，看到就知道是這兩件事之一。
動手試
把 S 改成 [ 5, 5, 5 ]，猜猜會印出什麼？再改成 [ ]（空的），猜猜會印出什麼？
03

字串也可以一個字一個字拿出來

for 不只能走清單，字串也可以——一次拿一個字。

清單裡放的如果是字串，s 每一輪接到的就是一整個字串，這時候還可以用 s[0] 拿它的第一個字。

3-5.py
name = [ "apollo", "vickey", "pig", "elsa" ]

for s in name:
    print ( s )
    print ( s[0], s[1] )
輸出apollo

vickey
v i
pig

elsa

如果直接把字串放在 in 後面，拿到的就是一個一個字元：

2.py
for char in "pig":
    print( char )
輸出p
i
g
  • s[0]第一個字。編號從 0 開始數，不是從 1。
  • s[1]第二個字。
  • 兩個 print都縮在迴圈裡，所以每一輪都會執行兩次，印出兩行。
容易踩的坑
編號從 0 開始，是 C 語言家族的共同規則，Python 也跟著。所以第一個字是 s[0] 不是 s[1]；四個人的清單最後一個是 [3] 不是 [4]。

range 產生一串數字：從哪開始、到哪停、一次跳幾

range(開始, 停止, 間隔)。停止的那個數字「不會」被印出來。

不是每次都有現成的清單可以走。要跑固定次數的時候，用 range 現場產生一串數字。三個參數可以只給一個、兩個或三個。

3-5.py
for i in range( 5 ):
    print ( i )

print ( "----------------------------------------" )

for i in range( 1, 5 ):
    print ( i )

print ( "----------------------------------------" )

for i in range( 1, 5, 2 ):
    print ( i )
輸出0
1
2
3
4
----------------------------------------
1
2
3
4
----------------------------------------
1
3
  • range( 5 )只給一個數字＝停止值。從 0 開始，到 5 之前停，所以是 0、1、2、3、4。
  • range( 1, 5 )給兩個＝開始、停止。1、2、3、4，沒有 5。
  • range( 1, 5, 2 )給三個＝開始、停止、間隔。從 1 開始每次加 2：1、3，再來是 5 但 5 要停了，所以只有 1 和 3。
  • range( 0, 5, 1 )課堂檔案最後還有這一個，印出來跟 range( 5 ) 一模一樣——因為開始值預設就是 0、間隔預設就是 1。
  • 分隔線課堂檔案在每段中間印一排橫線，不然三個迴圈的輸出會全部黏在一起分不出來。
容易踩的坑
停止值永遠不包含在內。range( 1, 5 ) 最大只到 4。想讓 5 也出現，要寫 range( 1, 6 )。這一條是整份筆記最常寫錯的地方，單元 09 會再講一次。
動手試
不要打開電腦，先在紙上寫下 range( 2, 6 ) 和 range( 1, 10, 3 ) 會印出哪些數字，再去跑跑看對不對。
05

間隔給負數，range 就倒著走

range( 5, 0, -1 ) 會從 5 數到 1。倒數的時候開始值要比停止值大。

間隔可以是負數。這時候第一個參數是大的、第二個是小的，整串數字就會由大到小。

for2.py
for i in range( 5, 0, -1 ):
    print ( i )
輸出5
4
3
2
1
  • 5從 5 開始。
  • 0到 0 之前停——所以印到 1 就結束，0 不會出現。
  • -1每次減 1。要印 10、8、6、4、2 就寫 range( 10, 0, -2 )。
容易踩的坑
倒著走一定要寫第三個參數。range( 5, 0 ) 少了 -1，Python 不會報錯，但會產生一串空的數字，迴圈裡面一次都不會執行——畫面什麼都沒有，看起來像程式壞掉。
動手試
寫一個迴圈印出 10、8、6、4、2。想好三個參數各要填什麼再動手。
06

range 不是清單，它只記住規則

range 不會把數字真的存起來，它只記得「從哪到哪、一次跳幾」，要用的時候才現算。

課堂筆記上寫 # tmp = [0, 1, 2, 3, 4] 是為了好懂。實際印出來看，它長這樣：

3-5-0.py
tmp = range( 5 )

print( tmp )
print( list( tmp ) )
print( tmp[4] )
輸出range(0, 5)
[0, 1, 2, 3, 4]
4

雖然不是清單，但它可以用編號取值、可以被 for 走訪、也可以重複走好幾遍，所以日常使用「把它當成一串數字」完全沒問題。

不真的存起來的好處是省記憶體。同樣是 0 到 9 這十個數字：

3.py
import sys

print( sys.getsizeof( range( 10 ) ) )
print( sys.getsizeof( list( range( 10 ) ) ) )
print( sys.getsizeof( range( 10000000 ) ) )
輸出48
136
48
  • 48range 不管裝幾個數字都是 48 個位元組，因為它只記三個數字（開始、停止、間隔）。
  • 136真的存成清單就要 136 個位元組，一千萬個數字就會把記憶體吃光。
容易踩的坑
直接 print( range( 5 ) ) 看到的是 range(0, 5) 而不是內容。想看內容要用 list( range( 5 ) ) 包一層。
動手試
猜猜 print( sys.getsizeof( list( range( 100000 ) ) ) ) 會印出多大的數字？再猜猜把 list 拿掉會印出多少。
07

迴圈跑完，迴圈變數還留著

迴圈結束後，那個變數不會消失，它停在最後一個值上——而且會蓋掉你原本同名的變數。

很多人以為 for i in ... 的 i 是迴圈的「內部零件」，跑完就不見了。不是的，它跟一般變數一樣留在原地。

4.py
num = "hellokitty"

for num in range( 10 ):
    pass

print( num )
輸出9
  • pass佔位用的關鍵字，意思是「這裡什麼都不做」。迴圈裡面不能空著，不寫東西就要放 pass。
  • 9原本的 hellokitty 被蓋掉了，剩下最後一輪的值 9。
容易踩的坑
這個問題在程式變長之後最可怕：上面用 i 存了使用者輸入的編號，中間跑了一個也叫 i 的迴圈，下面再用 i 就已經不是原來的值了。單元 21 會看到這個坑實際炸掉的樣子。
動手試
把上面的 num 改名成 i，其他都不動，猜猜結果會不會變？
CH 3 · 把數字一個一個加起來
08

累加器：先準備一個 t = 0，每輪往裡面加

t = 0 要放在迴圈「外面」，t += i 放在迴圈「裡面」。跑完 t 就是總和。

要算 1 加到 k，作法是準備一個袋子 t，一開始是空的（0），迴圈每拿到一個數字就丟進袋子。

3-6.py
k = int( input( "enter :") )
t = 0

for i in range( 1, k+1 ):
    t += i
print ( t )
輸出enter :5 → 15
enter :10 → 55
enter :100 → 5050
  • t = 0在迴圈外面。放進去的話每一輪都會歸零，最後只剩最後一個數字。
  • t += i等於 t = t + i。把 i 加進袋子裡。
  • k+1要算到 k，停止值就要寫 k+1。下一個單元專門講這件事。

看不出來 t 是怎麼變大的話，把中間過程印出來——這是看懂迴圈最快的方法：

5.py
k = 3
t = 0

for i in range( 1, k+1 ):
    print( "t =", t, "i =", i )
    t += i
    print( "加完 t =", t )

print( "總和 =", t )
輸出t = 0 i = 1
加完 t = 1
t = 1 i = 2
加完 t = 3
t = 3 i = 3
加完 t = 6
總和 = 6
容易踩的坑
把 t = 0 搬進迴圈裡面（跟 t += i 對齊），程式不會報錯，但答案會變成最後一個 i。k=5 時會印 5 而不是 15。不報錯的錯最難抓，所以才要印追蹤表。
動手試
把 t = 0 搬進迴圈裡跑跑看，確認真的會印出 5。然後搬回來。
09

要算到 k，停止值就得寫 k+1

range( 1, k ) 會少算最後一個。要包含 k 就要寫 range( 1, k+1 )。

這是單元 04 那條規則的實際後果。兩段程式只差一個 +1，k = 5 時答案差了 5：

少了 +1
k = 5
t = 0

for i in range( 1, k ):
    t += i

print ( t )
輸出10
正確
k = 5
t = 0

for i in range( 1, k+1 ):
    t += i

print ( t )
輸出15
  • range( 1, 5 )1 + 2 + 3 + 4 = 10。5 沒被加到。
  • range( 1, 6 )1 + 2 + 3 + 4 + 5 = 15。這才是「1 加到 5」。
容易踩的坑
這個錯不會報錯，只會算出一個「看起來很合理」的數字。檢查方法：拿 k = 1 去跑，答案應該是 1；如果印出 0，就是少了 +1。用最小的數字測試，是抓這種錯最快的辦法。
動手試
兩段都用 k = 1 跑一次，看看分別印出什麼。
10

迴圈裡放 if，就能挑著加

在迴圈裡放 if，符合條件才加——只加偶數就是 if i % 2 == 0。

% 是取餘數。i % 2 的意思是「i 除以 2 剩下多少」，偶數剩 0、奇數剩 1。

3-6-1.py
k = int( input( "enter :") )
t = 0

for i in range( 1, k+1 ):
    if ( i % 2 == 0 ):
        t += i

print ( t )
輸出enter :10 → 30
enter :7 → 12
enter :5 → 6
  • i % 2 == 0餘數是 0＝可以被 2 整除＝偶數。
  • 兩層縮排if 縮一層（在迴圈裡），t += i 縮兩層（在 if 裡）。縮排位置決定了它屬於誰。
  • print ( t )完全不縮排，所以是迴圈跑完才執行一次。縮進去的話每一輪都會印。
容易踩的坑
== 是比較，= 是賦值。寫成 if ( i % 2 = 0 ) 會噴 SyntaxError: cannot assign to expression here. Maybe you meant '==' instead of '='?——訊息後半直接告訴你該用 ==。這個在上一份筆記講過，迴圈裡一樣適用。
動手試
把 == 0 改成 == 1，k 輸入 10，猜猜會印出多少？
11

或者用 range 直接跳著走

range( 2, k+1, 2 ) 一開始就只產生偶數，連 if 都不用寫。

上一個單元是「全部走一遍，用 if 篩掉一半」。這裡是「一開始就只走偶數」。兩種寫法答案完全一樣：

3-6-1.py
k = int( input( "enter :") )
t = 0

for i in range( 2, k+1, 2 ):
    t += i

print ( t )
輸出enter :10 → 30
enter :7 → 12
enter :5 → 6

兩種都對，差在速度。一百萬個數字跑起來：if 版約 30 毫秒，跳著走版約 12 毫秒。因為跳著走只跑一半的圈數，而且不用每次算餘數。

  • if 版先全部走完再篩。好處是條件可以很複雜（例如「被 3 整除又是偶數」）。
  • 跳著走版只走需要的。好處是快，但只能處理「固定間隔」這種簡單規則。
容易踩的坑
要加奇數的話，開始值要改成 1 不是 2——range( 1, k+1, 2 )。開始值決定了從哪個數字起跳，改錯就整串都錯。
動手試
寫一個只加奇數的版本，k 輸入 10，答案應該是 25。
12

continue：這一輪不做了，跳下一輪

continue 會跳過這一輪剩下的程式，直接進入下一輪。break 是整個迴圈不跑了，continue 只跳過這一次。

跟單元 10 的 if 是同一件事的反面：if 是「符合才做」，continue 是「符合就跳過」。

6.py
for i in range( 1, 11 ):
    if ( i % 2 == 0 ):
        continue
    print( i )
輸出1
3
5
7
9
  • continue遇到偶數就跳過，底下的 print 不會執行。
  • 為什麼要用當「跳過」的條件很多、或是要跳過的程式很長時，用 continue 可以少縮一層排版。
  • 等價寫法if ( i % 2 == 1 ): print( i ) 結果完全一樣，兩種都對。
容易踩的坑
continue 和 break 很容易記反。口訣：break 是「打斷，整個不跑了」，continue 是「繼續，只跳過這次」。把上面的 continue 改成 break，輸出會只剩一個 1。
動手試
把 continue 改成 break 跑一次，確認真的只印出 1。
CH 4 · 在迴圈裡面再放一個迴圈
13

先做一列乘法表

固定一個數字，讓另一個數字從 1 跑到 9，就是一列乘法表。

這是九九乘法表的一半。先把一列做出來，下一個單元再把它變成九九。

99.py
N = int( input( "請輸入數字：" ) )

for i in range( 1, 10 ):

外面再包一層，就是九九乘法表

同一個迴圈，三種包法

函式有沒有參數、有沒有 return，決定了它能不能被重複利用。

同樣是 1 加到 k 的迴圈，包成函式有三種寫法。三個印出來的數字一樣，但能做的事差很多：

    for i in range( 1, k+1 ):
       t += i
    print ( t )


def my_count2 ( t ):
    for i in range( 1, k+1 ):
       t += i
    print ( t )


def my_count3 ( t ):
    for i in range( 1, k+1 ):
       t += i
    return  t

my_count2( total )
print( my_count3( total ) )

  • my_count3有參數，而且 return t 把答案交出來。這個才能拿去做別的事。

擂台法：先設一個擂台主，比贏的換人上

準備 MAX 記住目前最大值、winI 記住它的編號，走一遍，遇到更大的就換人。

這是找最大值的標準作法。MAX 像擂台上的擂台主，每來一個挑戰者就比一次，贏了就換他站上去。

4-8-0.py
S = [ 100, 89, 5029, 6000 ]

i = 0
MAX = 0
winI = 0

for e in S:
    if ( e > MAX ):
        MAX = e
        winI = i
    i += 1

print( "最大編號 : ", winI )
print( "最 大 值 : ", MAX )
輸出最大編號 :  3
最 大 值 :  6000
  • MAX = 0擂台一開始是空的，用 0 當起點。
  • winI = 0記住冠軍是第幾個。要拿名字的時候會用到。
  • i += 1手動數現在走到第幾個。注意它縮在 for 底下、if 外面——每一輪都要加，不是比贏才加。
  • e > MAX比目前的擂台主大才換人。用 > 不是 >=，所以平手時不換。
容易踩的坑
把 i += 1 縮進 if 裡面（跟 winI = i 對齊），編號就會全錯——因為只有「換人」的那幾輪才數數。這個錯不報錯，只會算出奇怪的編號。下一個單元的 enumerate 可以讓這個坑消失。

enumerate：編號跟東西一起拿

enumerate 會同時給你「第幾個」和「是什麼」，不用自己維護 i += 1。

上一個單元用了三行來管編號（i = 0、i += 1、還要注意縮排）。enumerate 把這件事包好了：

4-9.py
def find_max2 ( S ):
    MAX = 0
    winI = 0

    for(i, e) in enumerate( S ):
        if ( e > MAX ):
            MAX = e
            winI = i

    return winI


score = [ 100, 89, 29, 60 ]
print( find_max2( score ) )
輸出0

它實際產生的東西長這樣——每一份都是「編號, 東西」成對出現：

9.py
name = [ "apollo", "vickey", "pig" ]

print( list( enumerate( name ) ) )
print( list( enumerate( name, 1 ) ) )
輸出[(0, 'apollo'), (1, 'vickey'), (2, 'pig')]
[(1, 'apollo'), (2, 'vickey'), (3, 'pig')]
  • (i, e)一次接兩個值。i 是編號，e 是東西。括號可加可不加。
  • enumerate( S, 1 )第二個參數是編號從幾開始。預設 0，想從 1 開始就寫 1。
  • 少了三行i = 0 不用了、i += 1 不用了、縮排放錯的風險也沒了。

要講清楚一件事：enumerate 沒有比較快。一百萬筆資料實測，手動數 25.2 毫秒、enumerate 25.5 毫秒，幾乎一樣。它的好處是少寫三行、少一個會出錯的地方，不是速度。

容易踩的坑
輸入的編號通常從 1 開始（使用者習慣），程式的編號從 0 開始。enumerate( S, 1 ) 可以讓顯示的編號從 1 起跳，但這時候 i 就不能直接拿去當 name[i] 的索引了，會差一格。顯示用和取值用要分清楚。
動手試

為什麼一定要包成函式：i 會被蓋掉

擂台法裡的 i 如果直接寫在主程式，會把使用者輸入的編號蓋掉，程式直接崩潰。

單元 07 說過迴圈變數會留著。現在看它真的炸掉的樣子。假設使用者輸入 2，想查第 2 個人：

10.py

輸出Traceback (most recent call last):

MAX = 0 遇到全負數就會錯

擂台主從 0 開始，代表「比 0 小的數字永遠上不了台」。全部是負數時，答案會是錯的。

分數不會是負的，所以課堂範例沒問題。但換成溫度、盈虧這種會有負數的資料就會出事：

11.py
def find_max ( S ):
    MAX = 0
    winI = 0
    for( i, e ) in enumerate( S ):
        if ( e > MAX ):
            MAX = e
            winI = i
    return winI

print( find_max( [ -5, -2, -9 ] ) )
print( find_max( [ 7, 7, 3 ] ) )
輸出0
0
  • [ -5, -2, -9 ]正確答案是編號 1（-2 最大），但印出 0。因為沒有一個數字大於 0，擂台從頭到尾沒換過人。
  • [ 7, 7, 3 ]兩個 7 平手，印出 0＝第一個。因為條件是 > 不是 >=。想取最後一個平手的，改成 >=。

正確的作法是拿第一個元素當擂台主，而不是 0：

修好的版本
def find_max ( S ):
    MAX = S[0]
    winI = 0
    for( i, e ) in enumerate( S ):
        if ( e > MAX ):
            MAX = e
            winI = i
    return winI

print( find_max( [ -5, -2, -9 ] ) )
輸出1
容易踩的坑
這個改法有個前提：清單不能是空的，不然 S[0] 會 IndexError。Python 有內建的 max() 已經處理好這些狀況，實測也快兩倍——但先自己寫一遍，才知道它在做什麼。

for 是「跑固定次數」，while 是「跑到條件不成立為止」。

到目前為止都知道要跑幾次（清單多長、range 多大）。但像「一直問到答對為止」這種，次數事先不知道，就要用 while：

    print( n )

怎麼讀錯誤訊息

紅紅一大片不用全部看懂，照這三步走：

實際的錯誤訊息
Traceback (most recent call last):
  File "4-8.py", line 3, in <module>
    print( name[i] )
           ~~~~^^^
IndexError: list index out of range
  • 先看最後一行那是結論。IndexError: list index out of range 就是「編號超出名單範圍」。
  • 再看 line N它直接告訴你第幾行出事。跳過去看那一行就好，不用從頭找。
  • 中間可以跳過Traceback、檔案路徑、那排 ~~~~^^^ 是指出問題在哪個位置，看不懂沒關係。

迴圈常見的錯誤訊息

SyntaxError: expected ':'for 或 while 那行忘了打冒號。
IndentationError冒號下一行忘了縮排，或縮排的空格數不一致（混用 Tab 和空白）。
IndexError編號超過清單範圍。常見於迴圈變數被蓋掉（單元 21）。
TypeError: 'str' object cannot be interpreted as an integerrange 裡面放了字串，例如忘了 int( input() ) 的轉型。
NameError函式或變數還沒定義就拿來用。函式定義要放在呼叫之前。
KeyboardInterrupt不是錯誤，是你按了 Ctrl + C。

知道就好：迴圈的 else

Python 的 for 和 while 後面可以接 else，意思是「迴圈沒有被 break 打斷，順利跑完的話就執行」。

13.py
for c in "hello world":
    if ( c == "$" ):
        break
else:
    print( "字串裡沒有 $ 字元" )
輸出字串裡沒有 $ 字元

它是配 break 用的，不是配迴圈用的，名字取得很容易誤會。Python 的作者 Guido 自己也說過，如果重來一次不會加這個設計。看到別人寫會看懂就好，自己不用急著用。
