Git 基本流程

一個人做專案也用得上的最小工作流程。每個單元都是同一個順序：一句話重點 → 白話解釋 → 可以照打的指令 → 執行結果 → 容易踩的坑。不用背，照著打一次就懂了。

9 個單元 約 20 分鐘 範圍：init / status / add / commit / log / .gitignore / restore（不含分支、遠端）

CH 1 · 建立一個倉庫
01

版本控制在做什麼

Git 是幫專案存很多個「存檔點」的工具，每個存檔點都能回得去。

寫程式的過程常常會改壞東西、想不起來昨天改了什麼、或是想比較兩個版本差在哪。Git 每次存檔（commit）都會記下當時整個專案的樣子，之後隨時能回去看、能比較、能還原。不用 Git，「復原」只能靠自己複製一份 專案_舊版、專案_最終版、專案_真的最終版 這種資料夾。

02

git init：把資料夾變成倉庫

git init 是跟 Git 說「從這裡開始，幫我記錄以後的每個改動」。

在一個資料夾裡執行一次 git init，這個資料夾就變成一個 Git 倉庫（repository），底下會多一個藏起來的 .git 資料夾，所有歷史紀錄都存在那裡面。整個專案只需要在最上層的資料夾做一次，不要每個子資料夾都各做一次。

終端機 
$ git init -b main
Initialized empty Git repository in /Users/你/Desktop/demo/.git/
容易踩的坑
不要在使用者根目錄（像 ~/Desktop）直接執行 git init，會把整個桌面都變成追蹤範圍。先 cd 進專案自己的資料夾再 init。
03

三個區域：工作目錄、暫存區、倉庫

改動要先放進暫存區，才能存進倉庫，中間隔著你自己按下的確認動作。

工作目錄
你電腦上看到的檔案
正在改的東西，Git 還沒開始管它。
暫存區
git add 之後放的地方
打包好、準備存檔，但還沒真的存下去。
倉庫
git commit 之後存的地方
正式存檔，變成一個回得去的版本。

後面兩個單元的 git add、git commit 就是分別對應這三個區域之間的兩個動作，先搞懂這張圖，後面的指令就不是死背了。

CH 2 · 記錄每一次改變
04

git status：現在是什麼狀態

不確定現在改了什麼、進度到哪，永遠先打 git status。

這個指令只是「看」，不會改變任何東西，隨時打都安全。養成每做一步就看一次的習慣，比事後靠記憶猜好用。

終端機 
$ git status
On branch main

No commits yet

Untracked files:
  (use "git add <file>..." to include in what will be committed)
	hello.py
	memo.txt

nothing added to commit but untracked files present (use "git add" to track)
  • Untracked filesGit 還沒開始追蹤的新檔案，兩個都是剛建立、還沒 add 過。
  • No commits yet這個倉庫還沒存過任何一個版本，是全新的。
05

git add：放進暫存區

git add 不是存檔，是把改動放進「準備存檔」的箱子裡。

終端機 
$ git add hello.py
$ git status --short
A  hello.py
?? memo.txt
  • Ahello.py 已經放進暫存區，準備存檔。
  • ??memo.txt 還沒被 add，還停在工作目錄。
容易踩的坑
習慣打 git add . 會把整個資料夾的東西一次全部加進去，包含不小心留在裡面的密碼、大檔案。剛開始學，一個一個檔名點名加比較安全，或是先寫好 .gitignore（單元 08）再用 .。
06

git commit：正式存一個版本

git commit 才是真的存檔，而且一定要附一句話說這次改了什麼。

終端機 
$ git commit -m "Add hello.py"
$ git log --oneline
3ac9023 Add hello.py
容易踩的坑
commit 訊息不要寫 "update"、"fix" 這種看不出內容的話。半年後回頭找是哪一次改壞的，這句話是你唯一的線索。寫清楚「這次做了什麼」，不用寫「為什麼」。
07

git log：看歷史

git log --oneline 一行一個版本，新的在最上面。

終端機 
$ git log --oneline
679e158 Print a greeting twice
3ac9023 Add hello.py
  • 679e158每一行最前面這串英數字是這個版本的代號，之後要回到某個版本、或跟別人講「就是這一次改的」，靠這串代號指認。
CH 3 · 忽略與復原
08

.gitignore：不想被記錄的檔案

把不想讓 Git 管的檔案名稱寫進 .gitignore，它們就不會再出現在 git status 裡。

.gitignore 
__pycache__/
*.log
memo.txt
輸出 git status --short 只剩 M hello.py 跟 ?? .gitignore，memo.txt 不再出現
容易踩的坑
.gitignore 只對「還沒被追蹤過」的檔案有效。如果一個檔案已經被 git add 或 git commit 過，寫進 .gitignore 也沒用，Git 還是會繼續追蹤它，要先用 git rm --cached 檔名 把它從追蹤清單移除。
09

git restore：反悔怎麼辦

改壞了、想變回上一次存檔的樣子，用 git restore 檔名，還沒 commit 的改動會直接消失。

終端機 
$ git status --short
 M hello.py
?? .gitignore
$ git restore hello.py
$ git status --short
?? .gitignore
  • restore 前後M hello.py 那行消失了，代表 hello.py 已經變回上一次 commit 時的樣子，剛才寫的東西真的不見了。
容易踩的坑
git restore 是真的把還沒 commit 的修改刪掉，刪掉就找不回來了。先用 git status 或 git diff 確認真的要丟掉這個檔案的改動，不確定就先別動。
練習題

前四題各自對應前面幾個單元，最後一題把整個流程串起來，是這份筆記的大魔王題。每題都附「預期輸出」，自己跑完可以對答案，不用來問我對不對。

練習 1

建立第一個倉庫

新建一個空資料夾，cd 進去，執行 git init -b main，再打一次 git status 看看。

預期輸出 git status 會顯示「On branch main」跟「No commits yet」，沒有任何檔案列出來（因為資料夾裡還沒有東西）
練習 2

建立檔案並加進暫存區

在練習 1 的資料夾裡新增一個 notes.txt，寫幾個字進去，用 git add notes.txt 加進暫存區，再用 git status --short 確認。

預期輸出 git status --short 顯示 A notes.txt
練習 3

存第一個版本

把練習 2 加進暫存區的東西 commit 掉，訊息寫「Add notes.txt」，再用 git log --oneline 看一次歷史。

預期輸出 git log --oneline 顯示一行：一串英數字代號 + Add notes.txt
練習 4

忽略一個檔案

新增一個 secret.log（假裝是不想被記錄的檔案），寫一個 .gitignore，裡面加一行 *.log，用 git status --short 確認 secret.log 有沒有出現。

預期輸出 git status --short 只看到 ?? .gitignore，secret.log 不會出現
大魔王

從零開始跑完整套流程

新建一個資料夾，一次用到這份筆記教的每一件事：

01 git init -b main，建立倉庫。
02 建立兩個檔案：main.py（隨便寫幾行）跟 debug.log（假裝是產生出來的紀錄檔）。
03 寫一個 .gitignore，排除 debug.log。
04 把 main.py 跟 .gitignore add 起來，commit 一次，訊息寫「Initial commit」。
05 修改 main.py 隨便加一行，add、commit 第二次，訊息寫清楚這次改了什麼。
06 再改一次 main.py，這次改完反悔，用 git restore 復原，最後用 git log --oneline 確認整個過程只留下兩個 commit，debug.log 從頭到尾沒被追蹤過。
大魔王提示
.gitignore 要在 debug.log 被 add 之前寫好，順序顛倒的話單元 08 的坑會直接發生在你身上。
第 6 步的 git restore 只能救回「還沒 commit」的改動。如果不小心先 commit 了才想反悔，git restore 不是對的指令——這份筆記沒教怎麼救已經 commit 的東西，先想想看要不要另外問。
結束時 git log --oneline 應該剛好兩行，不多不少；如果變成三行，代表某一步 commit 了不該 commit 的東西。
