# 原始教材是雜亂筆記時：先整理再寫，不要照抄

使用者常常會直接丟一堆東西過來：手寫筆記轉出來的文字、上課投影片、好幾個 `.py` 練習檔、線上課程的講義。這些原始教材通常沒有順序、有重複示範、有錯字，甚至同一個觀念被講了兩三次。**不要照抄原始教材的順序或用字**，這份 skill 的工作是理解內容之後重新組織，不是排版搬家。

## 整理步驟

1. **全部讀完，列出清單**：把每一份原始教材都讀過一次，列出裡面出現的所有具體觀念、關鍵字、範例程式——是逐項列出來，不是寫摘要，避免漏掉細節。
2. **判斷底層邏輯，畫出依賴鏈**：對清單上每一個觀念問「要看懂這個，讀者要先知道什麼？」。答案決定單元的先後順序，也決定學習地圖要分成幾章。**這條依賴鏈才是分章分單元的依據，不是憑直覺分類**——跟「變數與判斷式」那份筆記把「存資料 → 做判斷 → 講結果」排成三章是同一個道理：後面的東西都要用到前面教過的東西。
3. **合併重複、去蕪存菁**：原始教材常常用兩三個不同檔案示範同一個觀念（例如三份練習檔都在教變數賦值），挑一個最能代表核心觀念、程式碼最乾淨的範例留下來，不用每份原始檔案的內容都塞進筆記。
4. **抓出「這樣寫會出錯」的段落，一定要留**：原始教材裡任何「老師特別強調」「這裡容易搞混」「這樣寫會出什麼錯」的內容，教學價值最高，一定要轉成對應單元的「容易踩的坑」，不能為了精簡而刪掉——這是這份筆記從第一版就重視的部分。
5. **辨認新舊寫法對照**：如果原始教材同時出現舊寫法跟新寫法（像 `%s`/`%d` 對 f-string），套用 `references/design-system.md` 裡「舊寫法 vs 推薦寫法」的雙 file-tab 配色，不用另外寫文字強調「這是新的」。
6. **練習題從依賴鏈自然長出來，不要另外發明**：步驟 2 畫出來的依賴鏈，每個節點對應一題練習，難度照鏈的順序漸增；最後把整條鏈串起來出小專案。練習題的內容要能回頭對應到這份筆記實際教過的東西，不要生出沒教過的概念。（「之後能拿來做什麼」區塊可以提到還沒教的套件，因為那是預告不是練習，規則見 `writing-style.md`「延伸應用」。）
7. **對照路線圖**：確認這份筆記是 `roadmap.md` 的第幾站、前面幾站有沒有已經教過的東西（例如迴圈筆記已經碰過函式），教過的用連結帶過，不要重教一次。

## 素材來自三方（老師的、使用者自己的、網路教材）時怎麼取捨

實際情況常常是三種來源同時出現：老師發的練習檔（檔名有規律，像 `3-6.py`、`4-8.py`）、使用者自己寫的練習（檔名沒規律，像 `test.py`、`99.py`）、使用者喜歡的網路教材。使用者講過的原則是「**我蠻喜歡我自己的，但如果因為效能跟正確性當然是以老師的為主**」，照這個順序處理：

1. **主線用老師的**。課堂檔案是教學順序的依據，筆記的單元順序要對得起上課進度，之後對照上課檔案才找得到。
2. **使用者自己寫的，只要沒錯就留著，而且要標出來**。那是他真的理解之後寫出來的，對他的記憶點最強。純粹風格不同（命名、括號、寫法）一律保留。
3. **使用者的版本有 bug 或效能問題，不要默默換成老師的**。明講哪一行錯、跑給他看錯在哪，再用正確版本。實際案例：使用者的函式在裡面又寫一次 `t = 0`，把傳進來的參數蓋掉，`f(100)` 跟 `f(0)` 結果一樣。
4. **老師的版本也可能有 bug，要逐一驗算**。實際案例：老師的 `2-4.py` 在退學判斷後面直接接 `if`，退學學生會被多印一行分數；同一份教材的 `2-4-1.py` 改成 `else` 才是對的，但後面的 `4-8.py`、`4-9.py` 又沿用了有 bug 的版本。**同一批教材裡出現兩個版本，優先用修好的那個，並且把「差一個 else 會怎樣」寫成一個坑。**
5. **網路教材補老師沒教到的洞**，不要拿來取代老師教過的東西。實際案例：課堂 13 個檔案裡一個巢狀迴圈都沒有，`continue` 跟 `while` 也沒教，這些從網路教材補進來；但字串格式化課堂用 `%d`、網路教材用 f-string，這種要用「舊寫法 vs 推薦寫法」的雙 file-tab 並陳，不是直接改掉。
6. **找出使用者自己早就寫對的東西，明講出來**。實際案例：使用者七個月前寫的正三角形程式，跟網路教材的「標準答案」逐行比對完全一樣。這種發現對信心的幫助比多教一個語法大，值得在單元裡寫一句。

## 課程不教的節點（自學補）

路線圖上標「自學補」的節點沒有老師的教材，主線換成：

1. **pythonbook.cc 對應章節**（`roadmap.md` 有列章節號）當主線順序，這是使用者常看、喜歡的寫法。
2. **Python 官方文件**補正確性，兩邊說法不同時以實際執行結果為準。
3. 筆記一樣照整套規則走（依賴鏈、驗算、練習題），header 的範圍說明要寫「課程沒教，自學補充」。
4. 網路教材的文字不能照抄，要用這份 skill 的語氣重寫；範例程式可以參考，但要改寫成自己的並實際跑過。

## 找錯改錯題的素材

照這個優先順序找：

1. **使用者自己寫錯過的程式**：`practice/README.md`「已知的問題」有整理好的清單（例如 `座標.py` 把兩個點的 X 湊成一組、`bmi.py` 的 `int()` 是無條件捨去）；批改時抓到的錯也算。自己犯過的錯最有記憶點。
2. **老師教材裡的 bug**（例如少一個 `else` 讓退學學生被多印一行）。
3. **筆記裡「容易踩的坑」寫過的錯**，改寫成一段會踩到的程式。
4. 都沒有才自己編，而且要是初學者真的會犯的錯，不要編冷門的語法陷阱。

`practice/` 裡的原始檔不能改（見 `practice/README.md`），出題時是複製內容進筆記，不是動原檔。

## 網路教材的範例也要自己跑過，不要因為是「出版品」就信

教材寫的跟實際跑出來的不一定一樣。實際案例：某份教材把兩段聖誕樹程式並列成同一個「標準版」的兩種寫法，實際跑出來寬度和對齊位置都不同（一個是靠左、寬度隨行變，另一個固定 15 字寬置中、右邊有尾空白）。畫面上看起來都是三角形，但拿去當練習題的「預期輸出」，學生會對不起來。

規則跟 `writing-style.md`「輸出結果一定要親自驗算」一樣，適用於所有來源：**沒有自己跑過的輸出，不准寫進筆記。**

## 教材量大時，先給大綱讓使用者確認

如果原始教材份量大（好幾份文件、好幾週的課程），**不要直接生出一整份完整 HTML**。先把步驟 1～2 整理出來的「觀念清單＋建議的章節與單元順序」用條列文字回報給使用者確認，確認章節切法沒問題，再開始寫完整的 HTML。這樣使用者能在動手寫之前先發現「這個觀念放錯章」或「這裡漏了什麼」，比整份寫完才發現要重排省事很多。

## 合併既有筆記

使用者手上有兩份（或以上）講同一個科目的筆記，要整理成一份時：

1. **兩份都讀完，各列一份觀念清單**，再對照：哪些兩份都有（合併成一個單元）、哪些只有一份有（補進對應章節）。
2. **以有完整排版、經過驗算的那份當底**，另一份（常常是簡短的備忘錄）的獨有知識點，改寫成這份的單元節奏（一句話重點 → 白話解釋 → 程式 → 輸出 → 容易踩的坑），不要整段貼過來。備忘錄裡的表格改成「簡易對照表」元件，提醒類的句子放進「容易踩的坑」。
3. **舊寫法逐條驗算，失效的要修，不要照抄。** 備忘錄常常是「自己用得順」的簡寫，沒在乾淨環境跑過。實際案例見 `writing-style.md` 第 5 點（`git pull` 的分岔問題）。
4. **編號變動要連動**：插入新單元後，後面的 `id`、編號徽章、學習地圖連結、文字裡寫的「單元 NN」、目錄頁的單元數與練習題數，全部同步改；跑一次 `.claude/hooks/check-html.py` 確認錨點沒斷。
5. **原有的練習題、大魔王題裡提到「這份筆記沒教」的句子，要回頭檢查**：合併之後可能已經教了（實際案例：大魔王提示原本寫「沒教怎麼救已經 commit 的東西」，合併後單元 11 教了）。
6. **被合併掉的舊檔不要自己刪。** 特別是還沒進版本控制的檔案，刪了就救不回來。合併完回報「內容已併入 XX，舊檔可以刪，要不要刪」，讓使用者決定。
7. 範圍有補的，記得更新 header 的「範圍」說明跟目錄頁卡片；沒涵蓋的（例如分支、衝突的解法）要在範圍裡明講「不含」。
