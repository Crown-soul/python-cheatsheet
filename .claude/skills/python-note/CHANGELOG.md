## v11 — 2026-09-23：修「選重複文字做筆記會跑到別段」的 bug

使用者回報：選某段文字做筆記存檔後，高亮會跑到頁面上另一段「長得一樣」的文字，不是原本選的那一段。

**根本原因**：`startNew()` 存筆記時用 `idx.full.indexOf(String(pendingRange).trim())` 找使用者選取文字在全文裡的位置，`indexOf` 只會回傳**第一個**符合的位置，跟使用者實際選的是第幾個完全無關。同一段文字在頁面上出現兩次以上時，存起來的「前文／後文」其實抄自第一次出現的位置，不是使用者真正選的那一次，`findRange()` 讀取時自然接回錯的位置。

- 新增 `globalOffset(idx, node, offset)`：`locate()` 的反向函式，把 DOM Range 的實際邊界點（節點 + offset）換算成全域字元位置，取代用文字內容反查。`startNew()` 改用這個算出真正的選取範圍，`quote`／`prefix`／`suffix` 三者都從這個位置切出來，保證是使用者真正選到的那一段，不會抄錯地方。
- 順手發現一個測試盲點：Python 的 `http.server` 沒送 `Cache-Control`，瀏覽器會用啟發式快取，重新整理、開新分頁都可能繼續吃到舊版 `annotate.js`，連 CDP 的 `cmd+shift+r` 都不保證繞得過去，唯一可靠的驗證方式是直接 `fetch(..., {cache:'no-store'})` 核對內容。**這個快取問題在正式站（GitHub Pages）對使用者也是真的**：修完 `annotate.js` 只 commit 是不夠的，使用者瀏覽器裡快取的舊版可能撐好一陣子。三份筆記的 `<script src="annotate.js">` 一律加上 `?v=2` 版本參數，之後每次改 `annotate.js` 都要把版號一起 +1，逼瀏覽器當成新資源重抓。
- 驗證方式：本機 `http.server` + 全新分頁（避開同分頁快取殘留）+ 網址加隨機 query 參數（避開整份 HTML 被快取）。故意選頁面上重複出現兩次以上的中文詞組（「冒號不能少」出現 2 次、「f-string」出現 12 次），分別選第一次／第二次／第三次出現的位置存檔，確認存檔內容跟高亮位置都準確落在使用者實際選取的那一次，重新整理後位置維持不變，兩則指向不同位置的筆記互不干擾。在 `loops.html` 跟 `variables-conditionals.html` 都測過。
- **這次修的是「寫入端」的邏輯**，`findRange()`（讀取端）沒有動：它原本就是用 `prefix + quote + suffix` 組合去精準比對，只要寫入端存的資料是對的，讀取端自然就對；`findRange()` 找不到精準組合時退化成單純比對 `quote`（原文被改掉時的模糊接回），這是既有設計、不是這次的問題範圍，不動它。
- **已經在使用者瀏覽器裡存壞的筆記救不回來**——localStorage 是本機資料，Claude 沒有存取權限，無法遠端修正。舊筆記要嘛刪掉重寫，要嘛用面板的編輯功能重新存一次（重新存檔會用新邏輯算出正確位置）。

skill 更新：`design-system.md` 跟 `SKILL.md` 都補上「改了 `annotate.js` 要把三份筆記的 `?v=N` 一起 +1」的提醒。
