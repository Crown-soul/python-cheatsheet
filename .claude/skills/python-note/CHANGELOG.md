# 版本紀錄

## v6 — 2026-09-20：三方素材取捨、效能主張要實測、網路教材也要驗算

起因：做「迴圈」這份筆記時，素材同時來自三個地方——老師的 13 個練習檔、使用者自己的練習檔、使用者指定的網路教材（pythonbook.cc）。三邊的寫法、正確性、效能說法都有衝突，現有規則只寫了「合併既有筆記」，沒有涵蓋這種情況。

- `source-material.md` 新增「素材來自三方時怎麼取捨」：主線用老師的、使用者自己的只要沒錯就保留並標出來、有 bug 不要默默換掉要跑給他看、老師的版本也要逐一驗算（案例：同一批教材裡 `2-4.py` 有 bug、`2-4-1.py` 修好了，但後面的檔案又沿用有 bug 的版本）、網路教材只補洞不取代、找出使用者早就寫對的東西要明講。
- `source-material.md` 新增「網路教材的範例也要自己跑過」：案例是某份教材把兩段輸出寬度不同的程式並列成同一個標準答案，當成練習題的預期輸出會讓學生對不起來。
- `writing-style.md` 新增「效能的說法一律實測」：三個實際遇到的說法全部不成立（`i++` 比較快、Python 自己的函式比較快、`enumerate` 比較快），規定要用 `timeit` 量過、數字要寫進筆記、沒差就明講沒差並說出真正的好處。
- 實際套用：`loops.html`，8 章 26 單元、23 個容易踩的坑、26 個動手試、22 題練習 + 3 題大魔王。
- 自我審核抓到並修掉的 bug：多處「輸出」欄位把多行結果壓成一行（`range` 三參數、`while` 對 `for`），改成照實際執行逐行列出並補回課堂檔案原本的分隔線；錯誤訊息只寫 `SyntaxError` 沒寫完整訊息；動手試叫學生產生一千萬個元素的 list（約數百 MB）；大魔王步驟敘述跟預期輸出互相矛盾。**這幾個都是「自己跑過但沒逐字核對」造成的，交付前要把輸出欄位跟終端機再對一次。**

## v5 — 2026-09-20：自動檢查 hook、參考解答、合併筆記

起因：使用者要把標籤與反引號檢查做成自動執行，補上練習題解答，並把 `git-cheatsheet.html`（備忘錄）跟 `git-basics.html`（講義）合成一份。

- 新增 `.claude/settings.json` 的 PostToolUse hook + `.claude/hooks/check-html.py`：每次 Write / Edit `.html` 都自動檢查標籤開合、殘留的成對反引號、內部連結與錨點。單獨一個反引號（VS Code 快捷鍵「⌃ `」）不算錯。對既有 5 份 HTML 零誤報；故意做壞的檔案 4 種問題都抓得到；在這個 session 實際觸發過，錯誤有回到 Claude。
- 檢查清單的第 1、2、8 點併成「自動檢查」，補上 Bash 批次改檔時 hook 不會觸發、要手動跑的提醒。
- 新增「參考解答」元件（`<details>` 摺疊）跟「簡易對照表」元件，見 `design-system.md`。解答預設仍然不附，使用者明確說要才加。
- 新增 `source-material.md`「合併既有筆記」流程。
- `writing-style.md` 補三條 Git 驗算規則：用乾淨環境跑（案例：`git pull` 在分岔時會 fatal，舊備忘錄「先 pull 再 push」在沒設 `pull.rebase` 的環境行不通）、遠端指令用本機 bare 倉庫模擬、會開編輯器的指令要加 `-m` / `--no-edit` 並在附錄講怎麼離開。
- 實際套用：`git-basics.html` 從 9 個單元擴成 14 個（新增 diff、amend、revert、GitHub remote、push / pull、push 被拒絕），加附錄（指令卡住、讀錯誤訊息、危險指令、名詞小辭典），練習題從 4 題擴成 7 題；Python 與 Git 的練習題都補了參考解答。
- 備註：建立 hook 的過程中，`.claude/settings.json` 和 `.claude/hooks/` 曾經在還沒 commit 的狀況下消失過一次（原因不明；`.claude/` 一開始在工作區是空的、skill 檔是從 git 還原的），重建後保持存在。commit 之後就受版本控制保護。

## v3 — 2026-09-20：補上環境卡關、批改流程、練習題可驗證性

起因：使用者反映筆記只教語法，沒教「程式怎麼跑不起來」，而這才是卡最久的地方；另外筆記完成後大量發生「學生貼程式碼問對不對」的情境，需要固定流程。

- 附錄新增兩個條件式必加區塊：「程式好像卡住了怎麼辦」（input() 存在就要加）、「怎麼讀錯誤訊息」。
- 練習題規則新增「預期輸出」：不給答案，但給可驗證的輸入輸出組合，讓學生不用問人也能自己核對。
- 題目敘述新增「單位跟邊界要寫死」規則。
- 新增整段「批改學生貼上來的程式碼」流程：先看題目要求 → 實際執行不要用讀的 → 測試結果列表格 → 問題分三級（會當掉／邏輯錯／風格不符）→ 每個問題指回筆記單元編號。
