# 版本紀錄

## v9 — 2026-09-21：選字做筆記（annotate.js）

使用者要能在筆記上畫重點、寫自己的備註，而且下次打開還在，但不能讓版面變亂。

- 新增專案根目錄的 `annotate.js`，三份筆記在 `</body>` 前各掛一行 `<script src>` 共用。骨架與檢查清單都補了這一條。
- 做法：選字 → 跳出「＋ 筆記」→ 右側面板顯示原文與輸入框 → 存進 `localStorage`（key 是 `mn:<檔名>`）。標記用「前文 30 字 + 引用 + 後文 30 字」定位，重新載入時再找回來塗色。
- **原文被改掉時不刪筆記**，標成「原文已變動」留在面板裡讓使用者自己決定（v8 之後筆記還會繼續改，這個情況一定會發生）。
- 版面：桌機面板從右側滑出並把內文推開（不是蓋住），手機改成底部抽屜佔約 72vh，關起來時版面跟原本完全一樣，只多一個右下角圓鈕。列印時整組隱藏、高亮去背。
- 踩到的坑：推開內文原本寫成改容器的 `margin-right`，但容器的 `margin:0 auto` 是 inline style 會蓋過樣式表，改成推 `body` 的 `padding-right` 才生效。
- **這個功能要在 http(s) 下才穩**：`file://` 開本機檔案時 Safari 會擋掉 `localStorage`。專案本來就有 GitHub Pages（https://crown-soul.github.io/python-cheatsheet/ ），README 跟目錄頁都改成建議從網址讀。面板下方有匯出／匯入，兼做備份跟跨裝置搬移。
- 驗證方式：用 `python3 -m http.server` 起本機伺服器實測，而不是用 `file://` 或靜態快照——`localStorage` 跟媒體查詢在後兩者下的行為跟真實情況不一樣。實測涵蓋：存檔、重新載入後高亮還原、跨 `<code>` 標籤的選取（`<code>` 結構要完整保留）、桌機推開不重疊、手機底部抽屜不產生橫向捲動。

## v8 — 2026-09-21：對齊骨架、修衝突、瘦身

起因：使用者要求全面巡一次 skill 有沒有衝突、謬誤，以及能不能用更少 token 達到同樣品質。

**修掉的衝突與謬誤**

- **骨架漏了「這份筆記怎麼用」**：`loops.html` 有這個虛線框（三輪讀法），另外兩份沒有，`design-system.md` 的骨架也沒寫。補進骨架第 4 塊，並補到另外兩份筆記（Git 那份的文字依科目調整成「開一個測試資料夾」）。
- **大魔王的位置沒寫清楚**：骨架寫「練習題最後一題大魔王」，但 `loops.html` 有 3 題、獨立成一個章節分隔線。補規則：只有一題就放練習題最後，超過一題要另開「大魔王」區段。
- **骨架沒寫哪種文件不適用**：`cheatsheet.html` 是純查詢用的小抄，整份都是「用查的」，硬套「要背的只有這幾個」會自相矛盾。骨架明講只適用「有學習順序的筆記」。
- **SKILL.md 有兩處過時**：開頭寫「兩份筆記」（現在三份）、檢查清單寫 hook「檢查三件事」（現在四件）。

**瘦身（同樣規則、更少字）**

- `design-system.md` 的 HTML 模板用 `{M}` / `{T}` 代替重複 36 次的 `font-family` 全寫，檔案開頭給對照表。`check-html.py` 新增第四項檢查：`style` 屬性裡出現沒展開的 `{M}` / `{T}` 就報錯——這個失誤瀏覽器只會靜靜忽略、字型掉回預設，人眼不一定看得出來，所以交給 hook 抓。
- `design-system.md`「要背的只有這幾個」原本同時用文字描述結構又附完整模板，刪掉重複的文字描述，只留選項規則 + 模板。
- `SKILL.md` 刪掉「使用時機」整段（跟 frontmatter 的 description、任務判斷表三重重複）、「互動習慣」裡跟前面重複的兩條、檢查清單重複的一條，並把 frontmatter description 壓短（每個 session 都會載入）。
- `CHANGELOG.md` 的 v1～v4 濃縮成四行摘要，保留 v5 之後的完整脈絡。

合計：SKILL.md 6981 → 6102 bytes、design-system.md 23559 → 22515 bytes（每次做新筆記都會載入這兩份，省的是每次的量）。CHANGELOG 的 v1～v4 壓掉 633 bytes，但這份文件本來就會隨著版本累積變大，而且不在自動載入路徑上。

## v7 — 2026-09-21：新增「要背的只有這幾個」

起因：使用者讀完「迴圈」筆記之後說「看一次記不得，但不看又好像沒學到」。追下去發現問題不在他——筆記把 26 個單元平鋪開來，讀者接收到的訊息是「這 26 個都要記」，於是全部都想記，結果全部記不住。筆記缺一條線，把「要背的」跟「用查的」分開。

- 整體骨架新增第 3 塊「要背的只有這幾個」，放在學習地圖後面、第一個章節分隔線前面（崩潰感是在看到單元總數那一刻產生的，要在那裡擋）。
- `design-system.md` 補元件規格與四條選項規則：每一項必須是**可以直接打出來的形狀**（知識點要包進形狀裡，寫 `k = int( input() )` 而不是寫「input 回傳字串」）、**上限 5 個且沒有下限**（湊數就退化成小抄）、判準是「沒背起來就打不出第一行」而不是「重要」、跟附錄檢查清單的分工是「打字之前」對「寫完之後」。
- `SKILL.md` 檢查清單新增第 7 條。
- 實際套用到三份筆記：迴圈 3 項（for 的形狀、range 三參數、累加器三個位置）、變數與判斷式 4 項、**Git 只有 2 項**（`add`→`commit`→`push`、`git status`），並在 Git 那份的引言明講「這一塊只有兩項，不是漏寫」，當作「沒有下限」這條規則的範例。
- 自我審查修掉的三件事：原本的提案把「形狀」跟「知識點」混在同一份清單（判準不一致，下次做筆記的人分不出該放什麼）；原本三份都寫「三個」是硬湊的配額；原本沒跟附錄既有的 9 項檢查清單分工，兩個清單會讓讀者混淆。

## v6 — 2026-09-20：三方素材取捨、效能主張要實測、網路教材也要驗算

起因：做「迴圈」這份筆記時，素材同時來自三個地方——老師的 13 個練習檔、使用者自己的練習檔、使用者指定的網路教材（pythonbook.cc）。三邊的寫法、正確性、效能說法都有衝突，現有規則只寫了「合併既有筆記」，沒有涵蓋這種情況。

- `source-material.md` 新增「素材來自三方時怎麼取捨」：主線用老師的、使用者自己的只要沒錯就保留並標出來、有 bug 不要默默換掉要跑給他看、老師的版本也要逐一驗算（案例：同一批教材裡 `2-4.py` 有 bug、`2-4-1.py` 修好了，但後面的檔案又沿用有 bug 的版本）、網路教材只補洞不取代、找出使用者早就寫對的東西要明講。
- `source-material.md` 新增「網路教材的範例也要自己跑過」：案例是某份教材把兩段輸出寬度不同的程式並列成同一個標準答案，當成練習題的預期輸出會讓學生對不起來。
- `writing-style.md` 新增「效能的說法一律實測」：三個實際遇到的說法全部不成立（`i++` 比較快、Python 自己的函式比較快、`enumerate` 比較快），規定要用 `timeit` 量過、數字要寫進筆記、沒差就明講沒差並說出真正的好處。
- 實際套用：`loops.html`，8 章 26 單元、23 個容易踩的坑、26 個動手試、22 題練習 + 3 題大魔王。
- 自我審核抓到並修掉的 bug：多處「輸出」欄位把多行結果壓成一行（`range` 三參數、`while` 對 `for`），改成照實際執行逐行列出並補回課堂檔案原本的分隔線；錯誤訊息只寫 `SyntaxError` 沒寫完整訊息；動手試叫學生產生一千萬個元素的 list（約數百 MB）；大魔王步驟敘述跟預期輸出互相矛盾。**這幾個都是「自己跑過但沒逐字核對」造成的，交付前要把輸出欄位跟終端機再對一次。**

## v5 — 2026-09-20：自動檢查 hook、參考解答、合併筆記

起因：使用者要把標籤與反引號檢查做成自動執行，補上練習題解答，並把 `git-cheatsheet.html`（備忘錄）跟 `git-basics.html`（講義）合成一份。

- 新增 `.claude/settings.json` 的 PostToolUse hook + `.claude/hooks/check-html.py`：每次 Write / Edit `.html` 都自動檢查標籤開合、殘留的成對反引號、內部連結與錨點。單獨一個反引號（VS Code 快捷鍵「⌃ `」）不算錯。對既有 5 份 HTML 零誤報；故意做壞的檔案 4 種問題都抓得到；在這個 session 實際觸發過，錯誤有回到 Claude。
- 檢查清單的第 1、2、8 點併成「自動檢查」，補上 Bash 批次改檔時 hook 不會觸發、要手動跑的提醒。
- 新增「參考解答」元件（`<details>` 摺疊）跟「簡易對照表」元件，見 `design-system.md`。解答預設仍然不附，使用者明確說要才加。
- 新增 `source-material.md`「合併既有筆記」流程。
- `writing-style.md` 補三條 Git 驗算規則：用乾淨環境跑（案例：`git pull` 在分岔時會 fatal，舊備忘錄「先 pull 再 push」在沒設 `pull.rebase` 的環境行不通）、遠端指令用本機 bare 倉庫模擬、會開編輯器的指令要加 `-m` / `--no-edit` 並在附錄講怎麼離開。
- 實際套用：`git-basics.html` 從 9 個單元擴成 14 個（新增 diff、amend、revert、GitHub remote、push / pull、push 被拒絕），加附錄（指令卡住、讀錯誤訊息、危險指令、名詞小辭典），練習題從 4 題擴成 7 題；Python 與 Git 的練習題都補了參考解答。
- 備註：建立 hook 的過程中，`.claude/settings.json` 和 `.claude/hooks/` 曾經在還沒 commit 的狀況下消失過一次（原因不明；`.claude/` 一開始在工作區是空的、skill 檔是從 git 還原的），重建後保持存在。commit 之後就受版本控制保護。
