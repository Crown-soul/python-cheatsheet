要背的只有這幾個，其他都用查的

14 個單元裡，沒背起來就打不出第一行的只有這三個形狀。其他 11 個單元，要用的時候回來查。

01巢狀迴圈的形狀
for N in range( 1, 10 ):
    for i in range( 1, 10 ):
        print( N, "*", i, "=", N * i )

內圈的 for 縮一層，print 縮兩層。外圈每跑一次，內圈就整個跑完一遍。

02函式的形狀
def my_sum ( k ):
    t = 0
    for i in range( 1, k+1 ):
        t += i
    return t

print( my_sum( 5 ) )

有 return 的函式，呼叫時要接住：存進變數，或直接放進 print。

03while 的形狀
n = 0
while ( n < 10 ):
    n += 1

條件用到的變數要先準備好，迴圈裡一定要有一行讓條件有機會變成不成立。

這些用到再查
enumerate 的第二個參數、break 跟 continue 哪個是哪個、三角形前面要補幾個空格、內建的 max()。
自我測試
關掉這一頁，開一個空白檔案，把上面三個形狀打出來。打得出來就往下讀；打不出來就回到這裡看一次，再關掉重打。

先做一列乘法表

固定一個數字，讓另一個數字從 1 跑到 9，就是一列乘法表。

這是九九乘法表的一半。先把一列做出來，下一個單元再把它變成九九。

99.py
N = int( input( "請輸入數字：" ) )

for i in range( 1, 10 ):
    print( "{} * {} = {}".format( N, i, N*i ) )
輸出請輸入數字：7
7 * 1 = 7
7 * 2 = 14
7 * 3 = 21
7 * 4 = 28
7 * 5 = 35
7 * 6 = 42
7 * 7 = 49
7 * 8 = 56
7 * 9 = 63

順便講一下三種把數字塞進文字的寫法。它們印出來一模一樣，差別只有寫起來順不順：

%d 和 .format()
N = 7
i = 3

print( "%d * %d = %d" % (N, i, N*i) )
print( "{} * {} = {}".format( N, i, N*i ) )
輸出7 * 3 = 21
7 * 3 = 21
f-string（推薦）
N = 7
i = 3

print( f"{N} * {i} = {N*i}" )
輸出7 * 3 = 21
  • %d最舊的寫法。老師的課堂檔案都用這個，要數好後面括號裡的順序。
  • .format()中間的寫法。大括號留空，值照順序填進去。
  • f-string最新的。引號前面加 f，直接把變數名寫在大括號裡，不用對照順序，最不容易出錯。

14

外面再包一層，就是九九乘法表

把固定的 N 也換成迴圈，就變成迴圈裡面還有迴圈。外圈每跑一次，內圈就整個跑完一遍。

上一個單元的 N 是使用者輸入的。現在讓 N 也從 1 跑到 9，一列就變成九列。

7.py
for N in range( 1, 10 ):
    for i in range( 1, 10 ):
        print( "{} * {} = {}".format( N, i, N*i ) )
輸出1 * 1 = 1
1 * 2 = 2
…（中略）…
1 * 9 = 9
2 * 1 = 2
2 * 2 = 4
…（中略）…
9 * 8 = 72
9 * 9 = 81
（總共 81 行）
  • 外圈 N跑 9 次。N = 1 的時候，內圈整個跑完 9 次，才輪到 N = 2。
  • 內圈 i每次外圈跑一輪，它就從頭跑完 9 次。所以總共 9 × 9 = 81 行。
  • 兩層縮排內圈縮一層，print 縮兩層。縮排錯了結果會完全不同。
容易踩的坑
如果把 print 只縮一層（跟內圈的 for 對齊），它就跑到外圈去了，只會印 9 行而不是 81 行。巢狀迴圈寫完，先數一下印出幾行，確認縮排沒放錯。
動手試
在外圈的 for 底下、內圈的 for 上面，加一行 print( "第", N, "列" )，看看它多久印一次。

巢狀裡的 break 只跳出最靠近的那一層

break 只會結束「包住它的那一個」迴圈，外面那層還會繼續跑。

把上面的九九乘法表加一個 break，讓每列只印兩個：

8.py
for i in range( 1, 4 ):
    for j in range( 1, 10 ):
        print( f"{i} x {j} = {i*j}" )
        if ( j == 2 ):
            break
輸出1 x 1 = 1
1 x 2 = 2
2 x 1 = 2
2 x 2 = 4
3 x 1 = 3
3 x 2 = 6
  • break跳出的是內圈（j 那一層）。
  • 外圈完全沒被影響，i 仍然從 1 跑到 3。
  • 結果每一列印兩個就換下一列，總共 6 行。
容易踩的坑
想一次跳出兩層迴圈，Python 沒有直接的寫法。常見作法是把內外圈包成一個函式，用 return 直接離開，第 5 章會學到。
動手試
把 if ( j == 2 ) 改成 if ( i == 2 )，猜猜會印出幾行？
16

break：找到了就不用再找下去

break 讓迴圈提早結束。找東西的時候，找到就可以停了。

走訪名單，印到 vickey 就停手，後面的 pig、elsa 不會被印出來：

3-5.py
name = [ "apollo", "vickey", "pig", "elsa" ]

for s in name:
    print ( s )
    if ( s == "vickey" ):
        break
輸出apollo
vickey
  • print 在前所以 vickey 自己會被印出來，才輪到 break。
  • break 在後如果把 break 寫在 print 前面，vickey 就不會被印。順序很重要。
容易踩的坑
課堂檔案寫的是 break;，結尾有分號。Python 不需要分號，加了不會錯但也沒用，那是 C 和 Java 的習慣。寫 break，不用加分號。
動手試
把 break 移到 print ( s ) 上面（兩行對調），猜猜輸出會變成什麼？

同一個迴圈，三種包法

函式有沒有參數、有沒有 return，決定了它能不能被重複利用。

同樣是 1 加到 k 的迴圈，包成函式有三種寫法。三個印出來的數字一樣，但能做的事差很多：

3-7.py
def my_count1 ( ):
    t = 0
    for i in range( 1, k+1 ):
       t += i
    print ( t )


def my_count2 ( t ):
    for i in range( 1, k+1 ):
       t += i
    print ( t )


def my_count3 ( t ):
    for i in range( 1, k+1 ):
       t += i
    return  t


k = int( input( "enter :") )
total = 0

my_count1( )
my_count2( total )
print( my_count3( total ) )
輸出enter :5
15
15
15
  • my_count1沒有參數，自己準備 t = 0，算完直接印。只能印，結果拿不出來。
  • my_count2有參數，從外面接一個起始值進來，算完直接印。一樣拿不出來。
  • my_count3有參數，而且 return t 把答案交出來。這個才能拿去做別的事。
  • k三個函式都沒有把 k 當參數，是直接讀外面的 k。能跑，但函式就綁死在這個 k 上了。

差別在最後一行。my_count3 的結果可以存起來、可以再拿去算，另外兩個印完就沒了。

容易踩的坑
函式定義要寫在呼叫之前。把 my_count1( ) 搬到最上面，會噴 NameError: name 'my_count1' is not defined。Python 是從上往下讀的，還沒看到定義就叫不出來。
動手試
把 my_count3 的 return t 改成 print ( t )，再跑一次。這時候畫面會變成四行，猜猜多出來的第四行是什麼？

參數被蓋掉、忘記接回傳值，都不會報錯

函式裡重新寫 t = 0，傳進來的參數就沒被用到；函式 return 了但呼叫時沒接住，答案也一樣不見。

這兩個錯的共同點是程式照跑、不報錯、但答案是錯的。

錯的：參數被蓋掉
def my_sum ( t ):
    t = 0
    for i in range( 1, 6 ):
        t += i
    return t

print( my_sum( 100 ) )
輸出15
對的：用傳進來的 t
def my_sum ( t ):
    for i in range( 1, 6 ):
        t += i
    return t

print( my_sum( 100 ) )
輸出115

傳 100 進去卻印出 15，代表那個 100 完全沒被用到。第二個常見錯是有 return 卻沒接：

忘記接回傳值
def my_sum ( t ):
    for i in range( 1, 6 ):
        t += i
    return t

my_sum( 0 )
print( "結束" )
輸出結束
  • my_sum( 0 )算完了，答案也交出來了，但沒有人接。那個 15 就這樣消失。
  • 怎麼接寫成 A = my_sum( 0 ) 再 print( A )，或直接 print( my_sum( 0 ) )。
底下發生什麼事（想深入再點開）

沒有 return 的函式，Python 會替它回傳一個特別的值 None，意思是「沒有東西」。把它印出來就看得到：

none.py
def say_hi ( ):
    print( "hi" )

A = say_hi( )
print( A )
輸出hi
None

所以忘了寫 return，呼叫的地方拿到的是 None，不是答案。

容易踩的坑
有 return 的函式，單獨呼叫一行是完全不會有任何畫面的。看到「跑了但什麼都沒出現」，先檢查是不是忘了接回傳值或忘了 print。

找最大值：用 MAX 記住目前最大的，遇到更大的就換掉

準備 MAX 記住目前最大值、winI 記住它的編號，走一遍，遇到更大的就更新這兩個變數。

這是找最大值的標準作法。MAX 記住目前看過最大的數字，每拿到一個新的數字就跟它比，比較大就換成新的。

4-8-0.py
S = [ 100, 89, 5029, 6000 ]

i = 0
MAX = 0
winI = 0

for e in S:
    if ( e > MAX ):
        MAX = e
        winI = i
    i += 1

print( "最大編號 : ", winI )
print( "最 大 值 : ", MAX )
輸出最大編號 :  3
最 大 值 :  6000
  • MAX = 0一開始還沒看過任何數字，用 0 當起點。
  • winI = 0記住最大值是第幾個。要拿名字的時候會用到。
  • i += 1手動數現在走到第幾個。注意它縮在 for 底下、if 外面，因為每一輪都要加，不是換掉 MAX 時才加。
  • e > MAX比目前的 MAX 大才換。用 > 不是 >=，所以一樣大時不換。
容易踩的坑
把 i += 1 縮進 if 裡面（跟 winI = i 對齊），編號就會全錯，因為只有換掉 MAX 的那幾輪才數數。這個錯不報錯，只會算出奇怪的編號。下一個單元的 enumerate 可以讓這個坑消失。
之後能拿來做什麼
資料分析之後用 pandas 處理成績表，找出最大值跟它是誰各一行就做完。這段先認得形狀，路線圖第 13 站會教：
pandas_max.py
import pandas as pd

score = pd.Series( [ 100, 89, 29, 60 ], index=[ "apollo", "vickey", "pig", "elsa" ] )
print( score.idxmax(), score.max() )
輸出apollo 100
動手試
把 S 改成 [ 6000, 100, 89 ]（最大的放第一個），確認編號印出 0。

enumerate：編號跟東西一起拿

enumerate 會同時給你「第幾個」和「是什麼」，不用自己維護 i += 1。

上一個單元用了三行來管編號（i = 0、i += 1、還要注意縮排）。enumerate 把這件事包好了：

4-9.py
def find_max2 ( S ):
    MAX = 0
    winI = 0

    for(i, e) in enumerate( S ):
        if ( e > MAX ):
            MAX = e
            winI = i

    return winI


score = [ 100, 89, 29, 60 ]
print( find_max2( score ) )
輸出0

它實際產生的東西長這樣，每一份都是「編號, 東西」成對出現：

9.py
name = [ "apollo", "vickey", "pig" ]

print( list( enumerate( name ) ) )
print( list( enumerate( name, 1 ) ) )
輸出[(0, 'apollo'), (1, 'vickey'), (2, 'pig')]
[(1, 'apollo'), (2, 'vickey'), (3, 'pig')]
  • (i, e)一次接兩個值。i 是編號，e 是東西。括號可加可不加。
  • enumerate( S, 1 )第二個參數是編號從幾開始。預設 0，想從 1 開始就寫 1。
  • 少了三行i = 0 不用了、i += 1 不用了、縮排放錯的風險也沒了。

要講清楚一件事：enumerate 沒有比較快。一百萬筆資料實測，手動數 25.2 毫秒、enumerate 25.5 毫秒，幾乎一樣。它的好處是少寫三行、少一個會出錯的地方，不是速度。

容易踩的坑
輸入的編號通常從 1 開始（使用者習慣），程式的編號從 0 開始。enumerate( S, 1 ) 可以讓顯示的編號從 1 起跳，但這時候 i 就不能直接拿去當 name[i] 的索引了，會差一格。顯示用和取值用要分清楚。
動手試
把 find_max2 的 enumerate( S ) 改成 enumerate( S, 1 )，猜猜印出來的編號會變成多少？

為什麼一定要包成函式：i 會被蓋掉

找最大值的迴圈如果直接寫在主程式，裡面的 i 會把使用者輸入的編號蓋掉，程式直接出錯。

單元 07 說過迴圈變數會留著。現在看它實際出錯的樣子。假設使用者輸入 2，想查第 2 個人：

10.py
name = [ "apollo", "vickey", "pig", "elsa" ]
score = [ 100, 89, 29, 60 ]

i = 2 - 1

MAX = 0
winI = 0
i = 0
for e in score:
    if ( e > MAX ):
        MAX = e
        winI = i
    i += 1

print( name[i] )
輸出Traceback (most recent call last):
  File "10.py", line 16, in <module>
    print( name[i] )
          ~~~~^^^
IndexError: list index out of range
  • i = 2 - 1使用者要查第 2 個人，i 應該是 1（vickey）。
  • i = 0 ... i += 1找最大值的迴圈把 i 當計數器用，跑完變成 4。
  • name[4]名單只有 0 到 3，所以 IndexError。

把找最大值的迴圈包成 find_max 函式就沒事了，因為函式裡的 i 是函式自己的，外面的 i 碰不到。這就是課堂檔案 4-8.py 要包成函式的理由，不是為了「看起來整齊」。

底下發生什麼事（想深入再點開）

在函式裡指定的變數，只存在函式裡面。函式外面有一個同名的變數，也不會被影響，兩個是不同的變數：

local.py
def find ( ):
    i = 99
    print( "函式裡的 i：", i )

i = 1
find( )
print( "外面的 i：", i )
輸出函式裡的 i： 99
外面的 i： 1

所以把找最大值的迴圈包進函式，裡面的 i 怎麼變，都碰不到外面使用者輸入的 i。

容易踩的坑
這種錯有時候更難發現：如果名單剛好夠長，不會 IndexError，只會默默查到別人的資料。所以不要靠「有沒有報錯」判斷程式對不對。
動手試
把上面找最大值的迴圈搬進一個 def find_max( S ): 裡面，確認最後印出的是 vickey。

MAX = 0 遇到全負數就會錯

MAX 從 0 開始，比 0 小的數字永遠換不上去。全部是負數時，答案會是錯的。

分數不會是負的，所以課堂範例沒問題。但換成溫度、盈虧這種會有負數的資料就會出事：

11.py
def find_max ( S ):
    MAX = 0
    winI = 0
    for( i, e ) in enumerate( S ):
        if ( e > MAX ):
            MAX = e
            winI = i
    return winI

print( find_max( [ -5, -2, -9 ] ) )
print( find_max( [ 7, 7, 3 ] ) )
輸出0
0
  • [ -5, -2, -9 ]正確答案是編號 1（-2 最大），但印出 0。因為沒有一個數字大於 0，MAX 從頭到尾沒換過。
  • [ 7, 7, 3 ]兩個 7 平手，印出 0＝第一個。因為條件是 > 不是 >=。想取最後一個平手的，改成 >=。

正確的作法是拿第一個元素當 MAX 的起點，而不是 0：

修好的版本
def find_max ( S ):
    MAX = S[0]
    winI = 0
    for( i, e ) in enumerate( S ):
        if ( e > MAX ):
            MAX = e
            winI = i
    return winI

print( find_max( [ -5, -2, -9 ] ) )
輸出1
容易踩的坑
這個改法有個前提：清單不能是空的，不然 S[0] 會 IndexError。Python 有內建的 max() 已經處理好這些狀況，實測也快兩倍。先自己寫一遍，才知道它在做什麼。
動手試

四個清單並排，用同一個編號串起來

name[i]、score[i]、live[i] 用的是同一個 i，所以同一個編號在四個清單裡指的是同一個人。

for 跑固定的次數；while 每一輪先檢查條件，條件不成立才停。

到目前為止都知道要跑幾次（清單多長、range 多大）。但像「一直問到答對為止」這種，次數事先不知道，就要用 while：

    n += 1
    print( n )

  • n < 10每一輪開始前檢查一次。成立就跑，不成立就結束。
  • n += 1一定要有東西讓條件有機會變成假。少了這行，n 永遠是 0，條件永遠成立，程式會一直跑下去。

    print( n )

容易踩的坑
無窮迴圈是 while 的條件永遠成立造成的：忘了改變數、或是改錯方向（該加卻減）。畫面會一直狂印或整個卡住，這時候按 Ctrl + C 中斷，會看到 KeyboardInterrupt，那是你自己按的，不是程式壞掉。

怎麼讀錯誤訊息

錯誤訊息照這三步讀：

實際的錯誤訊息
Traceback (most recent call last):
  File "4-8.py", line 3, in <module>
    print( name[i] )
           ~~~~^^^
IndexError: list index out of range
  • 先看最後一行那是結論。IndexError: list index out of range 就是「編號超出名單範圍」。
  • 再看 line N它直接告訴你第幾行出事。跳過去看那一行，不用從頭找。
  • 中間可以跳過Traceback、檔案路徑、那排 ~~~~^^^ 是指出問題在哪個位置，讀的時候可以先跳過。

迴圈常見的錯誤訊息

SyntaxError: expected ':'for 或 while 那行忘了打冒號。

延伸：迴圈的 else

Python 的 for 和 while 後面可以接 else，意思是「迴圈沒有被 break 打斷，順利跑完的話就執行」。

提示
退學那段要用 if / else 不是兩個 if，不然會印兩行（單元 24）。

序號 0 會變成索引 -1，Python 不會報錯但會查到最後一個人。i < 0 這個檢查不能省。
六種輸入都要測：0、1、2、3、4、5。
